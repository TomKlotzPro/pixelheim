# State and saves

Read before touching `GameState`, a state section, `SaveCodec`, `SaveSlots`, the Saves screen or the fixtures.

- Everything that persists lives in `GameState` (typed sections `hero`, `pack`, `settlement`, `progression`, `world`, and `post`) and changes only through its methods and its helpers (`GameState.upkeep`, `training`, `questing`, `holdings`, `spoils`, `trade`, `posting`...), which keep the save's invariants and call `mark_dirty()` / `save_now()`.
- **Saves are our own format, v5 (PIX-302, `SaveCodec`)**: one JSON file a slot, `user://saves/slot_<n>.save`: `pixelheim` (the format's version), `game` (the version that wrote it), `savedAt`, `playSeconds`, a `card` (name, role, look, worn, level, place, chapter, play time: what the Saves screen shows without the rest), then a section per part of the game, `hero`, `pack`, `home`, `town`, `story`, `quests`, `world`, `post` (once it holds anything), `buffs`. Nothing reads what only an old save held (PIX-319: no `legacy` section, no old mountain's floors, Deep Hunt or old throne's endings, no first-edition catch-ups in `normalize`; `valid_hero` refuses a hero missing a field rather than patching it). The fog is a bitmap per map (`WorldState.pack_fog`: the seen cells' box, a bit a cell, packed again only for a map seen more of). In play the state is one Dictionary in the game's own keys (`GameState.to_dict`/`apply`, the sections' `from_dict`/`write_into`); `SaveCodec.to_file`/`from_file` sort it into the file's sections and back, so a test's save and load is `SaveCodec.reread(state)`. A fully explored hero's save is 9 KB and writes in about 1 ms, read back and decoded (numbers in `perf.md`). Play time counts in `GameState._process` past the title for a hero in hand; leaving saves it even when nothing else changed.
- **Adding a field**: if an empty default is right for every save (a new list, a count from 0), add it to its state class (written once it holds something, read with that default) and to `to_file`/`from_file` in its section, with no version change (the Post's `lit`, PIX-323, and `hubs`, PIX-324, came in so). Anything else (a worked-out value for existing heroes, a field renamed, moved or changing meaning) bumps `SaveCodec.VERSION`, and until the beta **with no migration** (Tom, 2026-10-16): saves from before simply don't load, so say so in the release note. Compatibility (migrations, a frozen fixture per version) comes back at the beta. Prefer working a thing out from what's saved (the day, the seed, the lamps) over saving it. `test_save_codec` round-trips every fixture and a hero with every field set, so a field `to_file` forgets fails it.
- **Nothing from before v5 loads**: a slot holding only the first edition's `slot_<n>.json` is `older` (its own card, "Saved by an older version", never free, cleared with the damaged save's questions; the old file is never written), and a pasted `PXH1.` code or v1-v4 JSON says it's from an older version and loads nothing.
- **Codes are `PXH2.`**: base64 of a 4-byte checksum (SHA-256 of the rest), the file's size and the file deflated, so a code cut short or changed is caught. `SaveCodec.pasted(text)` reads a code (spaces and line breaks forgiven) or a v5 file's JSON and says why not (`older`, `newer`, `damaged`, `none`); `parse_any` is its state alone (the harness's `--load`). Parse JSON with `SaveCodec.parse_json` (it restores integers; plain JSON makes them floats and Godot would write `123.0`), and write it with `SaveCodec.serialize` (it keeps key order; `JSON.stringify` sorts keys by default).
- The fixtures (`test/fixtures/*.json`, the `slots*` folders' `.save` files) are v5 files, converted once by a throwaway script: nothing in the game converts. When the version bumps, write them again the same way. `slots_older/slot_1.json` is a first-edition save, for the older card.
- Slots: `user://saves/slot_<n>.save`. The user dir is pinned (`config/custom_user_dir_name="pixelheim"`): never change it, or players lose saves. Slot 0 (harness runs) never touches disk. Device settings live apart in `user://settings.cfg` (`GameSettings`, never in a save or a code).
- **No hero is lost to a file (PIX-303, `SaveSlots`)**: `write` puts the save in `.tmp`, reads it back and decodes it (`SaveCodec.decodes`), moves the slot's file to `.bak` (the save before) and renames the temp into place; a slot file it couldn't read goes to `.damaged` instead of over the good backup, and one a newer version wrote is never replaced. `look(slot)` says what a slot holds: `empty`, `hero` (from the file, a temp file a cut-off write left, or `backup` true: the save before, said on the card and in `GameState.slot_note`), `damaged`, `newer` or `older`; only `empty` is free (`is_free`, `GameState.free_slot`), so New Game and a pasted code never write over a save the game can't read, and the saves screen clears one only on a third X. Ask `look`/`summary(...)["kind"]`, never whether a summary is empty.
- **A new hero starts from the title's New Game alone (PIX-316)**: the saves screen has no New hero (an empty slot's E does nothing), creation takes `free_slot()`, and with none free (`GameState.room_for_hero()`) New Game says so under the menu and starts nothing.
- **Harness runs never write a slot**: they read fixture slots with `--slots <dir>` (read-only: never written or erased on disk, a run's own writes, deletes and R kept in memory so a flow sees them; `launch` boots its slot 1 as a launch would): `slots` (three heroes, the longest lines), `slots_room` (two heroes and an empty slot), `slots_unread`, `slots_backup`, `slots_older`; `--load <file>` plays a fixture save as a slot loads it; without either a run's slots are the player's, read-only too. Only `--slot N` writes, into the real save folder: agents never pass it.
- **When it saves, and the quill (PIX-302 step 4)**: `save_now(how)` saves at once and emits `saved(how)`: `MOMENT` by default (every save the game makes on purpose: entering a map but the first, a chest, a delivery or quest step, buying, funding, a skill, the title, the language, and a screen let go after a change, which `Screen` saves again even if the autosave kept it meanwhile, by `GameState.changes`), `QUIET` for the 3-second autosave and the saves on leaving, `SLEPT` for a night's sleep. The HUD's `Hud.Quill` (`world_hud.gd`, beside the clock, on the world's time so it waits under a screen) writes for about a second on a moment, with "Saved" under it on a sleep, never on a quiet save; Reduce motion shows it still. The pause menu's line under its title is `SlotCard.saved_ago` from `GameState.saved_clock` (GameClock). Report fields `quill=` and `pauseline=`; flows `saved-*`, `pause-saved*`. No save button anywhere: sleeping saves.
- **The Saves screen (PIX-302 step 3)** is one column: each card's lines come from `SlotCard` (pure: class and level, place and chapter, hours and when saved; no gold). E continues, D duplicates into the first empty slot, X asks then deletes: `SaveSlots.erase` keeps a hero aside as `slot_<n>.save.deleted` (the slot is free) until a `write` lands there, and R (`restore`) brings them back; C copies a `PXH2.` code, V pastes from the clipboard (asking before it replaces a hero; on the web it waits a moment for the browser's clipboard). A save it can't read clears on a third X, for good.
- **Where a save wakes**: a save on a dungeon floor wakes at the top of that floor (`Depths.waking`, flow `floor-resume`), one on the Night of Bells at its beat (flow `bells-resume`), one on ground that became cliff or that no walk from the spawn reaches on the nearest open ground that one does (`Ways.standing`). `--map <id>` boots at that map's spawn, not the save's position; `GameState.boot` runs once per session (slot switches reload the scene).
- A plain launch shows the title (harness runs skip it unless `title`); with no hero in the slot, a stand-in plays behind it and `GameState.save_now` writes nothing until `new_hero_in` / `import_into` / `play_slot` (`standing_in`).
- Web saves live in IndexedDB (`/userfs`); to check web-only behaviour see `verify.md`.

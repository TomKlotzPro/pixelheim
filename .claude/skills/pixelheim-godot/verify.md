# Verify: check.sh, CI, the harness, flows and the look book

Read before running anything, adding a flow, a report field, a harness flag or a look book shot.

## On the laptop: `check.sh quick`, then CI

**Run `godot/tools/check.sh quick` on the laptop, open the PR, and let CI run the full suite (PIX-272).** Several agents each running everything locally slow one another down. `quick` takes under a minute: the release, catalogue and layout checks, the tools' python tests when `godot/tools/*.py` or the export presets changed, the import only when the diff touches art, sound, fonts, scripts, shaders, scenes or tests (not the data's JSON) or a pull or rebase changed some since its last import, then GUT headless (failed on a `Parse Error` too) beside a headless boot of the town (day and night) and of the maps the diff touches, then the flows tagged with the areas the diff touches. It reads the branch's diff against `origin/main` (commits, uncommitted changes and new files). Everything is headless with `--audio-driver Dummy`: no window, no sound. Outputs stay in `godot/flows/check/`; a failed flow's own run is in `godot/flows/runs/<name>/` (`output.txt`, `godot.log`). Under load a flow can hit the watchdog: re-run it alone (`godot/tools/flows.sh --quiet <name>`) before believing the failure.

- `check.sh quick --plan` prints each changed file's areas and what would run, and runs nothing; `CHECK_FILES="godot/scripts/x.gd ..." check.sh quick --plan` previews any change. `check.sh full` runs everything CI runs, side by side, for the rare time the laptop must (CI down, a change to CI itself).
- `quick` warns when the main checkout's skill (the one agents load) isn't origin/main's (PIX-349): then read this worktree's own `.claude/skills/pixelheim-godot/`.
- **Tags**: each flow in `godot/tools/flows.txt` ends on its tags (`name | args | expected fields | town quest screen`), from the areas town, rooms, travel, field, combat, dungeon, trade, story, quest, screen, lang, save, gathering, title, rank, night (and `motion`). A script names the areas it touches on an `## areas: travel field +overworld*` line right under its `class_name`/`extends` (PIX-353; `all`, `none`, `+boot` names): **a new script gets that line**, which `test_areas.py` checks (every word a tag some flow carries). Every other file's areas are in `godot/tools/areas.txt` (`areas: globs`, first line naming the file wins, merged by union: add a line, never a glob twice). A file neither names, or whose areas no flow covers, runs every flow, and `quick` says so. A changed map also runs the flows that name it (and boots it), a changed `scripts/<x>.gd` the flows whose report shows `open=<x>`, a changed `flows.txt` the flows it adds or changes. A flow with no known tag runs every time.
- **The windowed motion flows never run in `check.sh`**: when the diff touches `player.gd`, `gait.gd`, `juice.gd`, `puny_art.gd`, `world_camera.gd` or `world_neighbours.gd` it says so. CI's windowed jobs walk `motion` and `line-motion` (over a line between two maps) on every pull request; `godot/tools/flows.sh motion line-motion` on the Mac is the fallback (it measures pixels, so it needs a window).
- **Integrating (the main session)**: when a rebased tree is identical to the one CI checked (`git rev-parse HEAD^{tree}` equals the tree of the commit whose CI run passed), rely on CI and run nothing locally. When a rebase had conflicts, run `check.sh quick` on the result and let CI run the rest on the pushed branch.

## CI (`.github/workflows/godot.yml`, every pull request)

- **`godot`** (headless): the tools' python tests, `release.py --check`, `layout.py --check`, the import (cached between runs), GUT (failed on `Parse Error` or `Failed to load script`: GUT exits 0 when a test file fails to parse and skips it), `i18n.py --check`, the web export, every map booted by day and at night (`flows.sh --boot`), then every flow headless (`flows.sh --quiet`). It fails on any FAIL, `SCRIPT ERROR`, `Parse Error` or `SHADER ERROR` (headless Godot still compiles the shaders it loads). With the paid art when the deploy key is there (a fork's PR runs on CC0 art alone, which every flow passes too).
- **`windowed (1)` to `(4)` and `windowed (look)`** (PIX-275, PIX-350): xvfb with Mesa's software rendering, **always on Shade's CC0 art alone** (the repository's artifacts are public). Each share runs every 4th flow in a window (`flows.sh --shard "$SHARE/4"`, the motion flows among them) and fails on any report that differs from what its flow expects; `look` runs the look book alone. None of them is a required check.
- **`pictures`**: every share's pictures on one contact sheet (`tools/flows_sheet.py`) and the look book's sheet, linked in a PR comment; "Every share passed". Judge the paid art's looks on the Mac (`flows.sh`, `lookbook.sh`, muted).
- **`Steady flows`** (`.github/workflows/flakes.yml`, nightly on main; `gh workflow run flakes.yml --ref <branch> -f runners=10` on demand) runs every flow round after round under load and names any that failed or changed its report.
- Timings are in `perf.md` (a run takes about 11-13.5 min).

## Commands

```sh
godot/tools/check.sh quick [--plan]                             # before every PR: what the diff could break, < 1 min
godot/tools/check.sh full                                       # everything CI runs, locally
godot --headless --audio-driver Dummy --path godot --import    # after new assets/scripts
godot --headless --audio-driver Dummy --path godot -s res://addons/gut/gut_cmdln.gd   # GUT; ALSO grep the output for "Parse Error"
godot --headless --audio-driver Dummy --path godot -- --help   # every harness flag, its argument and what it does
godot --headless --audio-driver Dummy --path godot -- --screenshot --map town fight kill   # a harness run (report line; no picture headless)
godot/tools/flows.sh --quiet [-j N] [--shard K/N] [name...]    # the flows headless, N at a time (cores-2), stepped
godot/tools/flows.sh --boot      # every map in the data booted headless, by day and at night (catches world.gd errors GUT can't)
godot/tools/flows.sh [--boot] --list   # the flows (or boots) with their tags, a line each
godot/tools/lookbook.sh [--desktop] [--looks browser,app] [--compare] [--only a,b]   # the look book (opens a window; --compare doesn't)
python3 godot/tools/flows.py match "<expect>" "<report line>"  # why a flow's expectation fails
python3 godot/tools/layout.py [--check]   # README's Layout from the scripts' first ## sentence
python3 godot/tools/i18n.py [--check]     # the catalogue
```

Windowed runs (`flows.sh` without `--quiet`, `lookbook.sh`, a harness run without `--headless`) open a window: keep them rare on the laptop, muted (`--audio-driver Dummy`), and leave visual review to CI's pictures unless the paid art's look is the question.

## The harness

- `harness.gd` is added only for `--screenshot` runs. It writes `godot/screenshot.png` (gitignored; `--shot <file>` elsewhere; none headless) and prints its report line, `screenshot saved; map=… cell=… hp=… gold=… …`. Read the PNG; the owner judges looks from screenshots.
- **Flags live in one table (PIX-262)**: `scripts/harness_flags.txt` declares every flag, its argument and what it does, a line each (`flag | takes | does`, PIX-356; `HarnessFlags.table()` reads it); `-- --help` prints it. Read flags through the one parse, `HarnessFlags.given()` (`flags.has("fight")`, `flags.value("--foe", "orc")`, `flags.list("--keys")`), never `OS.get_cmdline_user_args()`. A new flag is a new row with a name no other feature uses: `test_harness_flags` fails on a name declared twice, a flag read or passed (flows.txt, flows.sh, lookbook.sh, the README) that isn't in the table, or a row nothing reads. A flag's argument never reads as a flag (`--story ending_home` is not `ending`). A flag no flow, tool, doc or shot passes goes: PIX-352 dropped `--set`, `--role`, `ringtoss`, `levelup`, `--nodes`, `--cast`, `--take` and `--follow-wagon`.
- **Presets before the first map** are read in `world._ready` (world.gd), so the first map is drawn with them: `--town-tier`, `--built`, `--settlers`, `--prologue`, `--house-tier`, `--day`, `--seen`, `--hunted`, `--delivered` (PIX-348: Hale's order book lies open on the first map), `--post`, `--routes`, `--lit`, `--bells`; `GameState` reads a few more as it boots (`hints`, `--slots`, `--load`). **Steps** run in `harness.gd`'s `_run_test_harness`, in its own fixed order whatever the command line's.
- Harness runs play a throwaway hero, seeded (`GameState.HARNESS_SEED`). `--map <floor id>` stands the hero on a dungeon's floor (`vault_3`, `seacave_galleries`); `clear` fells every foe on the map, its guardian too. `overview` frames the whole map, `--at x,y` stands the hero on a cell, `--zoom Z` sets the camera (`--zoom play` is `CameraRig.ZOOM`, 3). `hints` turns the first-time hints on, as a new player has them (PIX-341). `cc0` holds the paid pack back where it's installed (PIX-318).
- Harness windows are always-on-top and never take focus (macOS stops drawing a covered window); `harness.gd`'s `_input` (it runs paused too) drops every event but its own and lets go of the actions they pressed. Keys go in with `--keys e,esc,...` (`harness._press`: `Input.action_press` plus `viewport.push_input`, stamped `harness.DEVICE`), because an unfocused window's keys are dropped by the display server.
- **Never pass `--slot N`**: it writes real saves to `~/Library/Application Support/pixelheim/`. Use `--slots res://test/fixtures/<dir>` or `--load <file>` (`saves.md`).
- Web-only behaviour (IndexedDB saves, the page's hooks): `godot --headless --path godot --export-release Web export/web/index.html`, serve `godot/export/web` with `python3 -m http.server`, drive it with Playwright, and inspect IndexedDB `/userfs`. Story or animation changes deserve a look there: a looping tween left on a freed node freezes the web's release build (`art.md`).
- macOS has no `timeout`; don't wrap commands in it.

## Adding a flow, a report field, a look book shot or a string never edits a shared line (PIX-273)

- *A flow* is one added line in `godot/tools/flows.txt`, `name | harness arguments | expected fields | tags`, under a comment saying what it walks through and its ticket (a flow right under another shares its comment), placed beside its kind, not at the end. `flows.sh` holds no flow and no sentence about them (`test_flows.py` fails on a flow without a comment, a name twice, a flow in flows.sh or a flow's ticket in flows.sh's comments). `.gitattributes` merges flows.txt by union, so two branches adding flows at one place keep both on a rebase; a flow both changed comes out twice and `flows.py` refuses it. The flags, report fields and shots below merge the same way (PIX-356), and `test_registries` refuses a name in them twice. They are read as they are, not imported: a file like them goes in every export preset's `include_filter` (`test_export.py`).
- *Expected fields* are `field=pattern`, matched **by name**, never by position: each pattern is a regex the field's whole value must match (`map=town` is not `town_shop`: `map=town_.*`; `open=shop_screen` is that screen alone), spaces allowed (`cell=\(79, 4\)`, `card=The Mirefen`), no `^`/`$`; a missing field fails.
- *A report field* is a line in `scripts/harness_report.txt` (`field | says`, PIX-356) in its place by name after the head (map … mobs), and its function `field_<name>() -> String` in `scripts/harness_report.gd` in the same place among the functions, returning "" when the run has none (the line leaves it out). A value the run knows only part-way (the counter's tab as it opens) is `report.note("tab", …)` in harness.gd and `return noted("tab")` in its function. harness.gd never writes ` name=` itself; `test_harness_report` fails on a field twice, out of order, without its function, built by hand in harness.gd, or expected by a flow and not in the table.
- *A look book shot* is a line in `scripts/lookbook_shots.jsonl` (PIX-356: a JSON object, its `shot` the **name**, `"strike"`, never `17_strike`; `cell` as `[x, y]`, `time` day, dusk or night) with its `area` from `Lookbook.AREAS` (town, rooms, reach, regions, ways, dungeon, combat, screens), among its area's shots; the sheet groups them by area. `lookbook.gd` says what each key does. `--only strike` takes the name; each folder gets `shots.txt` (the sheet's order) for `lookbook_compare.py`.
- *A string*: run `python3 godot/tools/i18n.py`. The catalogues' `#:` references name the file only, never the line, and entries sort by file then text, so editing a script changes `messages.pot`/`fr.po` only when one of its strings does (`i18n.py --check` refuses a reference with a line). In a conflict there, take both sides' entries and rerun `i18n.py`.
- *A script's doc*: the first sentence of its first `##` paragraph is its line in godot/README.md's Layout; run `python3 godot/tools/layout.py` after adding a script or changing that sentence. In a conflict there, rerun it.

## Flows are the same run every time (PIX-270, PIX-276)

- Each run has its own folder, `godot/flows/runs/<name>/`. A flow must pass in English and French (`FLOWS_EXTRA="--lang en"`): the CI runner is English, a Mac harness run follows the system's language. Don't edit `tools/flows.sh` while it runs (bash reads it as it goes; `flows.txt` is read once, at the start).
- `flows.sh` steps Godot (`--fixed-fps 60`, or a flow's `--fps N`), so every wait, timer, tween and key in a harness run is in the game's time, not the machine's; **time anything in play by `GameClock.seconds()`/`msec()` (the physics ticks), never `Time.get_ticks_msec()`** (only measuring the machine reads Time: `test_game_clock` fails otherwise), and draw dice from the global `randf()`/`randi()` or a seeded `RandomNumberGenerator`, never one left unseeded (Godot's particles draw from the same global dice, so the paid art's chimney smoke shifts a kill's loot against a CC0-only run: the same every run, but not across the two). A window draws a frame a second of the game's time (`--draw-every 60`) and every frame the harness reads the screen in: nothing the game decides may read what was drawn. No flow gets a second try. A report that differs between runs, or a flow that fails only in a window, is a bug.

# The screenshot harness's flags (HarnessFlags, PIX-262), a line each
# (PIX-356): `flag | takes | does` - the flag, the argument it takes (nothing
# between the bars for none) and what it does, for `-- --help`. In the order
# a run reads them: the boot's, then the harness's steps (harness.gd runs
# those in its own fixed order, whatever the order on the command line), then
# what the shot and the report line read. Two branches adding flags keep both
# on a merge (merge=union in .gitattributes); test_registries refuses a flag
# named twice, test_harness_flags one nothing reads.
--screenshot |  | a harness run: a throwaway hero (no slot read or written), the steps below, then screenshot.png or --shot's file (not headless) and the report line, and quit
--help |  | this table, then quit (nothing booted, no save touched)
touch |  | the phone's canvas: the screen's own shape, not letterboxed (PIX-162)
cc0 |  | the paid Medieval Age pack held back though it's here (PunyTown.available() false), as a build without the private art draws: no houses, props or signs, rooms from Shade's CC0 sheets (PIX-318)
--lang | <xx> | the game in that language for the run (PIX-195)
--pseudo |  | every string a third longer and accented: where a longer language would overflow (PIX-195)
--slot | <n> | play save slot n, not a throwaway hero (it WRITES the slot)
--load | <file> | play that save (a PXH2 code or a v5 file, res://test/fixtures) as a slot would load it, nothing written: where a save wakes (PIX-302)
still |  | Reduce motion on, as a player can set it
hints |  | the first-time hints on and none seen yet, as a new player has them (PIX-341)
--town-tier | <n> | the village at that age (default the Hamlet the flows were written for; 0 is a new hero's Ashes)

# The flows a release must not break (PIX-129), one a line, each driven
# through the screenshot harness on a throwaway hero by tools/flows.sh:
#
#   name | harness arguments | what the report must show | tags
#
# A new flow is a new line, under a comment saying what it walks through
# and its ticket (a flow right under another shares that one's comment):
# nothing else to edit. Put it beside its kind, not at the end.
#
# What the report must show: the fields of the harness's report line
# (scripts/harness_report.gd, HarnessReport.TABLE), `field=pattern`, matched
# by name, never by where they stand on the line. Each pattern is a regular
# expression the field's whole value must match: `map=town` is the town and
# not town_shop (`map=town_.*` for any of its rooms), `open=shop_screen` that
# screen alone. Spaces are fine inside a pattern (`cell=\(79, 4\)`); a field
# starts at the next ` name=`. A field the report doesn't show fails the
# flow, unless its pattern matches nothing at all: the report leaves out a
# field with no text, so `card=` expects no card up (PIX-371). Never `|` in
# a pattern: it parts the columns.
#
# The tags (PIX-272) are the areas of the game the flow walks through, which
# tools/check.sh quick matches against the files a branch changed (its AREAS),
# so the laptop runs only the flows the diff could break and CI runs them all:
# town (the village outdoors), rooms (inside a building), travel (doors,
# stairs, roads, passes, fast travel), field (what roams the open air),
# combat, dungeon, trade (shops, crafting, brewing), story, quest, screen
# (menus and pages), lang (every screen in French), save, gathering, title
# (the title and hero creation), rank, night, and motion (the windowed walk,
# which check.sh leaves to a human). A flow without tags runs in every quick
# check, so a new flow is never skipped.
